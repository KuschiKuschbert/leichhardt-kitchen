# Code contracts

Moved from `CLAUDE.md` on 3 November 2026, word for word except where marked, so that file holds rules and short warnings only. Each section is what a change to that part of the book must keep. CLAUDE.md links here under "Things that are easy to break". Where a feature note in `docs/` covers the same ground, that note wins.

## Class names

`.rail` is the steel shelf rail on the Pass; the landing and top bar use `.wtop`. Do not reuse class names across features (check `css/app.css` first).

## Shelves, tile groups and backHome()

Shelves (`.shelf`) and tile groups (`.tile-group`) use `content-visibility: auto`, so a plate in a group off screen has no true position until it is drawn. Coming back to Recipes goes through `backHome()` in `js/app.js` (draws every group once, puts the opened plate back, then skips again). Anything new that measures or scrolls to a plate in those lists needs the same. The tap feedback uses the `scale` property inside `:where()`, so it never fights a part's own `transform` or `transition`; do not switch it to `transform`.

## Writes go through W()

Every write goes through `W()` in `js/prep.js`, which adds the writer's id (`by`). The rules check that phone's PIN session (`sessions/<uid>`), and for the admin also the matching device grant (`adminDevices/<uid>`, see `docs/device-sessions.md`; updated 3 Nov 2026, was "since phase 2 nothing else"), and a write made while a session is being opened waits for it (`sessP`). Direct `setDoc` calls bypass the staff lock and are refused. To ask whether this phone may write as the person signed in, use `canW()`, never `S.tok` (a phone that opened with its session has no PIN fingerprint in hand). PIN tries are one every 20 seconds per person (rules), so a test that types two PINs for one person runs the clock on 21 seconds between them; the test phones start with a running session (`tests/lib.js`, `o.oldTok` for the older proof).

## Security header and test helpers

The security header in `index.html` lists every outside service the book may load. A new one (a script, a font, an API, a frame) has to be added there or the browser blocks it. Keep scripts in files: inline `<script>` blocks and `onclick=` attributes do not run. In tests use `L.waitFor`, not `page.waitForFunction`, and `L.settle(p, ms)`, not `p.waitForTimeout(ms)` (it stops early once the page is still, but still waits for any timer due in that time). A check on something read from Firestore (a count, a card, a badge) waits for that thing itself with `L.waitFor`; the page can go still before a slow read comes in, and the test then fails only under load.
