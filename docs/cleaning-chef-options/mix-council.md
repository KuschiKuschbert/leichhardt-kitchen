## Recommendation

**First build: retain A, Grouped notebook. Best later mix: A with B's setup editor, M1.** Do not describe the hybrid as the council's immediate build recommendation; every reviewer currently prefers plain A.

If a mix is selected, keep A's daily folds, visible shared work, exception links, numeric pack-down order and inline checks. Borrow B's adjacent task list/editor only inside Repeat tasks on a laptop. Keep one inline form on phones. This places editing beside the selected task without carrying B's phone group grid or task-page navigation into daily work.

Defer C's weekly board unless actual week review shows that A's day/group browsing is insufficient. Its due-task counts must never imply known service coverage or missed cleaning. Defer the full A+B+C mix; all reviewers ranked it last.

## Tap cost, visibility and invariants

The proposed mix leaves A's daily taps unchanged: open group, disclose task, K required-check taps, Record. For Clean impingers, K=2, so five taps from a closed Hot larder group versus four for the current visible task, excluding scrolling. A later six-row page adds one. Shared devices retain the existing worker choice.

At council review, all mixes retained A's initial phone overview of five groups and zero complete task rows in the original schematic frame. No hybrid density, editing-speed improvement, recovery behaviour or read budget had been measured. The owner subsequently asked to see M1: [the concrete preview and local measurements](mix-preview.md) now illustrate it, without changing these votes or establishing real application recovery or speed.

Keep one source of task, completion and editor state. Preserve unsent work across group changes, dates, resizing, device locks and application updates. Reuse loaded tasks; read the existing bounded week range only on Week entry. No polling, extra listener, duplicate editor/save route, new permission or persistent private cache is proposed.

## Refinements that do not require a larger mix

- Use clear Open tasks wording as well as an expanded state, rather than relying on a plus sign.
- Keep shared General cleaning first, and blocked/Pass summaries visible across the kitchen.
- Explain what is left, what is recorded and what event coverage is unknown. Keep today's progress explicitly labelled when Week is open.
- Consider showing the next incomplete task in a closed group, then measure the additional space before adopting it.

These are recommendations, not accepted requirements. Implementation still needs actual role, draft/recovery, read-budget, keyboard, contrast, target-size and completion checks. The owner has requested advice, not chosen a layout.
