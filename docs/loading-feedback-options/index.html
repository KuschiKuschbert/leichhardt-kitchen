Loading and Feedback Options

An audit of every wait, save message and toast in the book, and two redesigns for each of six moments: opening the book, opening a kitchen page, a tap, a save, a toast with Undo, and lost signal. Each one starts from Ink in motion, chosen on 3 November: the traced icons, the pencil placeholder lines and the rule that a tick only shows once the server has it all stay.

Press a button above a strip and all three phones play the same moment, under one clock. The first phone is how the book behaves today.

Found in the audit

Source read across js/, the page's own markup and CSS, plus browser checks with the click tests' stand-in for Firebase. Fix needs no design choice. Design is what the options above answer. Speed and Tidy are measured or source findings for later small pull requests.

Shared groundwork, whichever you pick

These hold for every option and are worth doing first, because each design above needs them.

One toast, one save state

Today there are four toast copies (the prep pages, the landing, and three identical ones in the recipe, drawing and function editors) and about a dozen message slots. One shared helper for each, used by every page, keeps the cached-module rules for older saved copies.

Same words for the same wait

Openingfiles and editors: "Opening the recipe editor..."
Readingkitchen data: "Reading today's list..." (replaces most "Loading...")
Checkingsign-in and access: "Checking your PIN..."
Saving / Sendingwrites, Sending for mail only
No signalthree sentences, not seven: page waits, change waits, read failed

How long things stay

  • A confirmation: 4 s.
  • Undo: 9 s, as now.
  • An error: until OK, Try again, or the problem is gone. Never a timer.
  • Slow save note: after 4 s everywhere (now 3, 4, 5 or 10 s).

Build steps

The head chef chose the recommended set on 4 November 2026. Small pull requests in this order, each with click tests at 390, 768 and 1280 px, the reads budget check and reduced motion:

  1. Fix the stale Undo (LF-01, LF-02). A failed save removes its own Undo, and the older Undo lasts its full time. Test fails first on today's code.
  2. Toasts: the docket slip on every page, including the editors and the landing. Errors get a red edge and stay.
  3. Saving: the button tells the story, form by form, starting with pings, minutes and deliveries, with the shared save words.
  4. Signal: the floating band, also carrying the update offer.
  5. Opening and pages: steady shell and same page, filling in. Touches index.html and the saved-shell file lists, so it goes last and alone.
  6. Speed: answer the tap first, Recipes drawn in pieces. Measured before and after on the same slowed phone.

How the numbers were taken. The book from main at 01227ea, served locally, opened in headless Chromium with the CPU slowed 4 times, with the click tests' stand-in for Firebase (answers in about 5 ms). Real Firestore, App Check and sign-in add network time that these numbers do not include. Five reloads per figure, median shown. Not yet checked on a real phone, an iPhone or with a screen reader.

Demo timings on this page follow those measurements, slowed or shortened where marked so the difference is easy to see.
