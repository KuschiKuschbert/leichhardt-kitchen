## Cross-feature preservation checklist

- Keep four outcomes distinct: a staff order request, a supplier order with quantities, reminder-only Mark order done, and a delivery receipt. Applying a suggestion changes the draft. None authorises contacting a supplier.
- Function revisions/cancellation/Undo update only matching generated prep/order effects, preserving completed ticks and immutable history; contact data never enters printing.
- Supplier catalogue names, stable ids and explicit units feed ordering and source identity, while training and analysis preserve source/unit/direction distinctions.
- Prep recorded-doer credit and authenticated recorder activity remain separate; no extension of the Prep trial to Wastage/Transfers.
- Corrections invalidate historical copies on other devices; manual proofreader repairs do not rewrite already-counted learned totals. Nightly analysis rereads corrected sources.
- A successful range cache needs every part. Offline/failed read state must survive view changes and cannot become an empty complete report or CSV.
- Device mode, remembered Google, live PIN unlock, admin device grant, personal daily lock, shared idle lock and voluntary handover remain separate concepts.
