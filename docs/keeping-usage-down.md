# Keeping usage down (3 Nov 2026)

Moved here word for word from `CLAUDE.md` on 11 Nov 2026, so that file stays short. `CLAUDE.md` keeps the short version; this note is the full rule.

Measured on 2 and 3 November 2026: about 45 pull requests in two days, 100 Click tests runs at 20 minutes each (33 hours of runner time; 21 cancelled by a newer push, 16 failed on timing), and 52 "merge `main` into the branch" commits across 40 pull requests. Most of the cost was repeated test runs and reading big files, not the work itself.
- **Read big files in parts.** `docs/prep-book.md` is about 300 KB, `README.md` about 160 KB, `docs/head-chef-decisions.md` about 90 KB, and `docs/ux-council-audit.md`, `docs/whole-app-audit.md` and `docs/whole-app-inventory.md` are 30 to 72 KB each. Never read one whole: search for the heading or word you need (Grep), then read that part only. The audit notes are for audit work only.
- **Keep this file short** (8 Nov 2026). It loads in every session and every agent, so every 4 KB here costs about 1,000 tokens each time. A new note or file gets one short row here; its dates, the design chosen, its tests and the detail go in `docs/session-map.md` or its own note.
- **Let the queue bring `main` in.** It updates one ready pull request at a time (How changes ship, step 7). Merge `main` in yourself only to fix a conflict, once. Every merge of `main` starts another Click tests run (about 6 minutes on five runners); with several sessions open that multiplies.
- **Push when the work is finished.** Each push cancels the running Click tests and starts again. Make the fixes, run the files you changed (How changes ship, step 2), then push once.
- **Every merge costs the kitchen's reads** (5 Nov 2026). A new version reloads the screens left open (at most once an hour) and every phone that comes back, and each reload reads its lists again. 48 merges in a day helped use up the free 50,000 reads by 13:00. Group small changes to one page in one pull request. Since 5 Nov 2026 ready pull requests merge only in the two release windows (`docs/auto-merge.md`).
- **Wait without spending.** One check-in per pull request (about 50 minutes, then 4 hours). Do not poll, do not re-read a pull request that has not changed, and do not reply to a notice that needs nothing.
- **A timing failure is not your bug until it repeats.** When Click tests fails on a test your change does not touch, read the failing test's name first. Re-run once; if it fails again, or a different timing test fails, say so in the pull request and fix it in its own pull request.
- **Agents only where they pay.** Use parallel agents for the service council (once per major decision, not per push) and wide audits. Do a lookup, a single file or a known fix yourself.
- **Few sessions at once.** Three or four open pull requests merge smoothly; eight make each other run Click tests again and again. Group small changes to one page in one pull request when they share the same files.
- **Keep "Require branches to be up to date before merging" on** (head chef, 4 Nov 2026). `main` goes straight to the phones, so every pull request is tested against the exact `main` it joins; two that pass alone can still break together. Cut the catch-up cost with fewer sessions and the queue bringing `main` in one pull request at a time, not by turning the setting off. A merge queue would remove the waiting but needs an organisation-owned repository.
- **Ready means merge in the next release window.** Mark a pull request ready when it is finished and stop: the Auto-merge workflow merges it in the next window and brings `main` in one at a time (How changes ship, step 7). No waiting, no polling for the merge. `urgent` is for a fix the kitchen needs now, not to skip the wait.

## What GitHub enforces (checked 22 Oct 2026)

- `main` is protected: the **Click tests** check must pass and the branch must be up to date with `main`; force pushes and deleting `main` are refused.
- Not enforced by GitHub: reviews (none required, Claude merges by the head chef's decision of 21 Oct 2026), and the protection does not apply to admins. The main-branch guard hook (`scripts/guard-main.mjs`) stops Claude Code sessions from working on `main`; a person with admin rights can still push to it.
- The **Click tests** job checks `js/*.js`, `js/lib/*.js` and `sw.js` parse, runs the click tests, then the rules checks on the Firestore emulator (`tests/rules`) and the nightly learning check (`scripts/emulator-check.mjs`), since 22 Oct 2026. A pull request that changes only `*.md` files or files under `docs/` passes after the parse check in about a minute (3 Nov 2026); do not put anything the book loads or a test reads under `docs/`. Since 4 Nov 2026 the browser files run in five shares of equal work on five runners at once (by `tests/timings.json`, longest files first; refresh it with `UPDATE_TIMINGS=1` when one share is clearly slower), with the rules beside them, about 5 to 6 minutes instead of 25. A file that takes longer than any share runs in parts beside itself (`offline-writes.test.js` and its `-2`, `-3` files, 4 Nov 2026); the job named **Click tests** collects them. A file still running after 10 minutes is stopped and counted as failed (`FILE_TIMEOUT`, 4 Nov 2026), so a hang no longer holds a runner to its 30 minute limit. A failed file runs once more on its own: a pass then shows as a "passed on retry" warning, and the same file passing on retry twice is a bug for its own pull request: the weekly issue "Click tests that needed a second try" (`scripts/flaky-report.mjs`) lists them, marked Yes. When a run fails, read its annotations or summary first (`gh api repos/<owner>/<repo>/check-runs/<id>/annotations`), not the whole log.

## The right model for the job (24 Nov 2026)

The head chef shared a video on getting Opus-level thinking without paying Opus prices for every step, and asked to use each model where it is best. Fable is in the head chef's plan (the head chef checked, 24 Nov 2026). `CLAUDE.md` cannot choose a model: it only gives instructions. The model is a setting or a plugin, so the session's model comes from the **model-router** plugin on the head chef's Claude account, the advisor from `.claude/settings.json`, and each helper agent's model from its Agent call.

**One model per session.** Most of what a session saves comes from the prompt cache, and the cache belongs to one model. Switching on every message would write the whole conversation again at the new model's price. So the router picks where a switch is cheap: at the start of a session and when a helper agent starts fresh.

| Model | Used for | How it is set |
| --- | --- | --- |
| Haiku, Sonnet, Opus or Fable | The main session. Haiku reads the first request (about 300 tokens) and picks: Haiku for a quick question, Sonnet for everyday work (the default), Opus for a short but hard problem, Fable for a big or risky job. The next two requests may move it up a tier, never down; then it stays | The model-router plugin (`/router` shows the pick and why, `/router off` stops it, `/model` wins) |
| Sonnet | The main session on a computer without the plugin | `"model": "sonnet"` in `.claude/settings.json` |
| Fable | The advisor in every session. It sees the whole conversation and is asked before an approach is chosen, when an error keeps coming back and before the work is called done | `"advisorModel": "fable"` in `.claude/settings.json` |
| Fable | The council's skeptic and keeper of the book (Try to break it, failure and recovery) | `model: "fable"` on their Agent calls (`.claude/skills/service-council/SKILL.md`) |
| Opus | The other council reviewers, the screen designer and wide-audit reviewers: judgement that counts, many at once | `model: "opus"` on their Agent calls |
| Sonnet | A helper agent with a known job: write or check code a set way | `model: "sonnet"` on its Agent call; the router sets Sonnet when none is named |
| Haiku | A helper agent that finds, searches, reads a log or fetches a page | `model: "haiku"` on its Agent call; the router sets Haiku for Explore and the other lookup agents |

**What it saves and what it costs.** Everyday sessions run on Sonnet instead of Opus and lookups on Haiku: that is most of the saving. The router's own check costs about 300 Haiku tokens per request in a session's first three requests. Two council reviewers move from Opus to Fable, so a council round costs more than before: the reviews that look for failures get the strongest model. Fable is the biggest model, so expect it to use the plan's allowance faster than Opus; the docs give no figure. Not measured yet: compare the plan's usage page in Claude settings after a week of sessions.

**Which setting wins.** Highest first: `/model` in the session, then `--model` at launch, then the `ANTHROPIC_MODEL` environment variable, then `"model"` in the settings files. On a computer (the Mac), the project's `"model"` applies at every new session. In a cloud session started from the Claude app it does not: the model picked when the session is created wins (tested 24 Nov 2026: a session started on Opus on this branch ran on Opus, with the project settings loaded), and the docs offer no way to force it short of an organisation-wide lock. The router gets round that: it rewrites each request of the main conversation to the model it picked, whatever the app picked.

**Checked here (24 Nov 2026).** The `advisor` tool appeared in a running cloud session as soon as `"advisorModel"` was added. In local runs started on Opus, the router sent a git question to Haiku, a unit test request to Sonnet, a tricky intermittent bug to Opus and a security rules redesign to Fable; Opus answered only the bug. In a session the head chef started from the app on Opus, with the plugin saved to the account, `/router` said "This session runs on Sonnet (everyday work)" and every reply came from Sonnet. Sessions started by another session (`create_session`) do not load account plugins, so test the router from the app. The router's source and its 13 tests travel as the `model-router.plugin` file the head chef saved; it is not in this repo.

**Good to know.**
- The advisor is marked experimental in the Claude Code docs. If it is not available, the session runs without it; nothing breaks.
- A Fable request that a safety check refuses can re-run on Opus by itself (`switchModelsOnFlag`).
- An Agent call's `model` takes only the short names: `haiku`, `sonnet`, `opus`, `fable`.
- `opusplan` (Opus in plan mode, Sonnet otherwise) was weighed and not chosen: sessions here rarely use plan mode, and there is no Fable version. The advisor works without plan mode.
- To plan something big, say so in the first message: a big or risky request goes to Fable. Or type `/model fable` (or `/model opus`), which the router leaves alone. Plan mode works on whichever model the session runs.
